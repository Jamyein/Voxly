# Lessons Learned

> Compressed 2026-08-01: 46 entries merged into 18 themes. Old numbering in git history.

## 1. JNI/native exports & release verification
- `@CriticalNative` on `companion object` methods is instance-level → release ART verifier rejects. Use `@FastNative` or a Java static-native class (JNI sig `(JNIEnv*, jobject, ...)`).
- Name-discovered Companion natives resolve as `..._Foo_00024Companion_...` (add `00024Companion`); prefer `RegisterNatives` in `JNI_OnLoad` (errors surface at load; only `JNI_OnLoad` needs `global:`).
- A linker version script `local: *;` strips JNI symbols from `.dynsym`, which ART `dlsym` searches — `strings` lies. Verify with `llvm-nm --dynamic --defined-only | grep Java_` (flag `T`), never `strings`. Keep `-keep class Foo$Companion`.
- ART verification is stricter in release: verify JNI with `minifyReleaseWithR8` + running the release APK; debug-only checks miss failures.

## 2. Hilt/DI
- `@AssistedInject` VM: never default `= hiltViewModel()` (created without the factory callback) — pass the VM from the nav entry.
- `Context` in a `@HiltViewModel` must be `@ApplicationContext` (ViewModel scope binds only that).
- VMs can't inject VMs (`ViewModelValidationPlugin`): stateful helpers are plain `@Inject` classes with their own `CoroutineScope(SupervisorJob() + Dispatchers.Main.immediate)`.
- Hilt AP bundles an old `kotlin-metadata-jvm` → after every Kotlin major, force-upgrade via `resolutionStrategy.eachDependency` (fails `hiltJavaCompile`). Verify: `:app:dependencies --configuration kspGithubDebug | findstr metadata-jvm`.

## 3. Coroutine scopes
- Never `viewModelScope.launch(context: Job)` — work becomes a child of that Job, not the scope; `onCleared()` won't cancel it. Use `launch { supervisorScope { ... } }`.
- Post-save side effects (DB writes, event emissions, cache invalidation) must run on `@Named("ApplicationScope")` — `viewModelScope` dies with `onCleared()`, leaving the cache stale.
- Helpers with their own scope leak across VM recreation: expose `dispose()`/`clear()` that cancels the Job and resets StateFlows; the owner calls it in `onCleared()`.

## 4. Flow/event discipline
- Events → `MutableSharedFlow(replay=1, extraBufferCapacity=64, DROP_OLDEST)` + `tryEmit`; `MutableStateFlow` conflates (faster emissions get overwritten). No seed → subscribers trigger their own initial load.
- Never `.sample()` a flow carrying terminal state (a COMPLETED just before completion is dropped); use `debounce`.
- Emit the terminal event in every path (empty/all-failed batches too) or the UI stays in-progress forever.
- `x.let { state.update { it } }` — the inner `it` is the StateFlow's current value (shadowed), silently no-ops. Use a named param: `info -> _flow.update { info }`.

## 5. coerce/index pitfalls
- `coerceIn(min, 0)` throws when a bound is 0 at first composition — guard `if (containerHeight <= 0f)`.
- `indexOfFirst().coerceAtLeast(0)` turns "not found" (-1) into slot 0 — handle -1 explicitly (score lowest priority on miss), never coerce the index.
- Unbounded similarity scaling (`1 + (sim*10).toInt()`) lets partial matches outrank exact — clamp tier scores with `.coerceIn(...)`.

## 6. MediaCodec decode
- `KEY_SAMPLE_RATE` on the input format is ignored; decoders output native rate. Decimate PCM post-decode and init the scanner at the actual rate (or `KEY_OUTPUT_SAMPLE_RATE`, API 35+).
- `flush()` throws unless Started — reuse after `stop()` = `configure()` + `start()`; on stop failure `release()` (native cleanup), don't pool; `closeAll()` after scans.
- Vendor bug: some FLAC extractors report `audio/raw` for compressed data — try the extension-based MIME decoder FIRST, fall back to raw on failure, recreating BOTH extractor + scanner (histogram is poisoned). Detect failure via exceptions AND null/non-finite gain.
- Genuine `audio/raw` → read directly via `readSampleData()`/`advance()`; raw-decoder passthrough is ~20x slower.
- `MediaCodecList.findDecoderForFormat` returns first match (may be software) — iterate `codecInfos`: pass 1 HW-accelerated non-alias `isFormatSupported`, pass 2 software fallback.
- Offline/batch decode: async `setCallback()` (dequeue* polling blocks 10ms/iter); `onInputBufferAvailable`→queue, `onOutputBufferAvailable`→process PCM, `onError`→latch. No dequeue* in async mode; `flush()` in async mode needs `start()` after.

## 7. Material3 1.5.0-alpha25
- `ToggleButtonDefaults.shapes()` is `@Deprecated(level=HIDDEN)` (JVM method exists, Kotlin-source invisible) → build `ToggleButtonShapes` from composable `val` properties (`ToggleButtonDefaults.shape`, no parens). On a bump, `javap` the AAR class and check for `DeprecationLevel.HIDDEN` before assuming a rename.
- `MenuDefaults.itemColors()` renamed `trailingIconColor` → `trailingContentColor` (also `disabledTrailing*`). "No parameter with name 'X'" = param rename — read the compiler's candidate list.
- Tooltip APIs (`TooltipBox`, `PlainTooltip`, ...) are `@RequiresOptIn(level=ERROR)` gated by `ExperimentalMaterial3Api` (≠ Expressive) — `e:` = hard failure; opt into all families; `javap -v` shows the gating annotation.

## 8. Room/SQL performance
- Never put expressions (`COALESCE`, `SUBSTR`, arithmetic) in indexed `ORDER BY`/`WHERE` (full scan + in-memory sort, ~50ms/10k) — add a write-time-computed column + index. Prefix matching → range queries (`path >= :dir AND path < :dir || 'zzzzzzzz'`), not `GLOB`/`LIKE`.
- `withContext(IO)` around Room suspend DAOs and self-threading suspend fns is redundant — use it only for blocking Java I/O (`File`, `java.io`), `contentResolver.query`, non-suspend I/O utils.
- `stateIn()` only when something collects the flow directly; a `combine()` uiState sole consumer should reference the DataStore flow directly (~49 wrappers → ~33% bloat).

## 9. Room PK identity
- A PK must be an immutable deterministic function of the natural identity, generated identically at every site. `AudioFile.id` came from 3 algorithms (MediaStore `_ID` / 32-bit `path.hashCode()`), mutating the PK on first save + `INSERT OR REPLACE` clobbering distinct files on hash collision.
- Per-file cache identity is `path` (v15: no `id`; FTS4 joins on base `rowid`; paths normalized at the persistence boundary). Any future `id` field needs a written argument; `CachedAudioFileIdentityTest` asserts no `id` field.

## 10. Metadata fallback & selection
- Album selection must filter by the source file's `ALBUM = ?` (optionally `ARTIST = ?`) — `IS NOT NULL` returns the whole library; always include the source `filePath`.
- Same-field cross-source fallback (`album = lightweightResult ?: cached`) is mandatory KEEP; cross-field fallback (`albumArtist → artist`) is a removal candidate. Audit: `grep -rn "album = lightweightResult\|album = cachedFile\|albumArtist = " app/src/main/java/`.

## 11. AGP 9 build config
- Do NOT apply `kotlin("android")` on AGP 9+ (fatal config error); the `kotlin { }` block still works. Compose/Serialization/KSP/Hilt plugins still apply.
- `applicationVariants.all` is deleted → use `androidComponents.onVariants` (read ABI from `output.filters`, versionName from `defaultConfig`).
- `-Pandroid.injected.build.abi` is an internal Studio flag — breaks ABI splits in AGP 9 (100KB stub APK). Use a custom property (`-PbuildAbi`) wired into `splits.abi.include(...)`; search `app/build/outputs/apk/`, sort by mtime.
- CI: PR builds must fall back to `assembleDebug` when signing secrets are absent (fork PRs have none); never loosen the Gradle signing assertion.

## 12. Edit discipline — batch coordinated changes
- Switching to an experimental API (`FlowRow` → `FlexBox`) needs import + `@OptIn` + usage in one batch; after a `git checkout` revert, re-verify all three.
- Deleting an import → grep remaining usages (params, returns, generics) before recompiling.
- Replacing one collector with another: grep for pre-existing collectors of the same flow first. A replacement that happens to duplicate an existing collector's shape (e.g. two identical `scanState.collect` blocks) silently double-emits errors/toasts.

## 13. Retrofit `@Body` must be `@Serializable`
- Every `@Body` data class (and nested types) needs the annotation — the converter is built from it at runtime; the compiler accepts unannotated bodies but Retrofit throws on first call. Compile success ≠ runtime.

## 14. Cache-serving short-circuits must respect `bypassVersionCache`
- A refresh that "succeeds" without scanning hides staleness. Whitelist cache-serve returned without `scanDirectoriesIncremental` (the only path that diffs current paths + purges deleted rows), and the start gate compared two pre-deletion counts (both predated the change → no scan ran). For un-notifiable sources (SAF): incremental scan on resume/start (`bypassVersionCache=true`), coalesced by `collectLatest` + a resume throttle.

## 15. `WindowSizeClass` import source
- `currentWindowAdaptiveInfoV2()`'s `WindowSizeClass` lives in `androidx.window.core.layout`, NOT `material3.adaptive.layout`.

## 16. No `runBlocking` in Composables
- `remember { runBlocking(IO) { ... } }` blocks the main thread during composition → ANR on large album art. Use `produceState(initialValue, key) { value = withContext(IO) { ... } }`; if the loader is already suspend, call it directly.

## 17. Fallback chains must sync the tracking set
- When a fallback mutates a subset copy, sync the original tracking collection after each step (`remaining.clear(); remaining.addAll(remainingSet)`) or the next step re-processes removed items → duplicate groups.

## 18. LazyList scroll metrics = viewport, not content
- `layoutInfo.viewportEndOffset` is the viewport height, so `scrollableRange ≈ 0`. Normalize by index: `firstVisibleIndex / (totalItems - visibleCount)`; never treat `viewportEndOffset` as content size.

## 19. Interface methods carry defaults — moving them loses the defaults
- An override with no explicit default inherits the base's default parameter values; call sites on the subtype compile. When an interface method is removed and its body moves to the concrete class as a standalone (non-override) member, those inherited defaults disappear → `No value passed for parameter 'X'`. Re-declare the default (`= null`) on the concrete member when delisting from the interface.


## 20. KDoc closure when deleting functions
- Deleting a function body while its KDoc stays orphaned above leaves the block unclosed (\*/\ removed with the deleted lines) \Syntax error: Unclosed comment\. When removing a doc'd function, delete its KDoc block in the same edit, or leave the \*/\ intact.

## 21. PowerShell 5.1 `Get-Content`/`Set-Content` default to ANSI (GBK), not UTF-8
- Reading a UTF-8 file with bare `Get-Content` and re-writing with `Set-Content -Encoding UTF8` silently mojibakes every non-ASCII char (GBK round-trip) and can merge lines; the damage is irreversible once written. Never use PowerShell cmdlets to edit UTF-8 files — use the Read/Edit tools (exact-match, byte-preserving). If PowerShell is unavoidable, use `[System.IO.File]::ReadAllLines($p, [Text.Encoding]::UTF8)` / `WriteAllLines` with an explicit UTF8 encoding (no BOM).

## 22. Derived-flow conversion: "map has key" checks silently invert semantics
- Converting a manually-maintained `MutableStateFlow<Map<K,V>>` to a `combine(...).stateIn(...)` derived flow changes the *presence* semantics: a grouping helper that initializes a key for every selected dir (even an empty list) makes `key in derived.value` permanently true. Any `all { it.uri in map }` skip-gate then always fires (skipping the cold-start scan), and `alreadyLoaded` checks flip from "has data" to "is selected". Re-derive the intent, not the expression: check `map[key]?.isNotEmpty() == true` for "has files", and drop skip-gates whose redundancy now lives in the callers.

## 23. M3 Scaffold doesn't auto-pad content away from bottomBar — the content lambda MUST apply innerPadding
- M3 Scaffold (1.2+) does NOT constrain the content area to avoid topBar/bottomBar; the content lambda receives `innerPadding` (topBar/bottomBar heights + contentWindowInsets) but the content must apply it itself. Ignoring it (`{ _ -> ... }`) fills the whole Scaffold and the bottom bar covers the bottom of every screen hosted inside.
- `contentWindowInsets = WindowInsets(0)` only zeroes the *system-inset* part of contentPadding; the bottomBar slot's measured height is ALWAYS included. An outer shell Scaffold hosting a NavDisplay with a bottom NavigationBar must wrap its content in `.padding(innerPadding).consumeWindowInsets(innerPadding)` — the padding collapses to zero automatically when the bar hides (AnimatedBottomBarContainer), which is what gives the list the extra rows the hide animation promises.
- `consumeWindowInsets(innerPadding)` forwards the reservation so inner screens' own `WindowInsets.navigationBars` reads (FAB `navigationBarsPadding()`, list `contentPadding`) return only the remainder — without it those paddings double up.

## 24. State published asynchronously (via a DataStore collector) lags the scan it must filter
- `WhitelistRepositoryImpl.add/removeWhitelistDirectory` mutated a local list + wrote DataStore but NEVER assigned `_whitelistDirectories.value` — the StateFlow updated only via an async collector, so `filterSettings`/`filteredAllAudios` could run with stale whitelist paths when the scan finished writing to Room. Freshly scanned files get filtered out (logs show the scan, UI shows nothing). Rule: when a repo method mutates the state it exposes, publish the StateFlow synchronously in the same call; the DataStore collector is only a fallback sync.
- `AlbumArtistAggregator` read `filteredAllAudios.value` inside cache-event handlers (`FilesBatchUpdated`, filterSettings/separator collectors, `incrementalUpdateFile`). Cache events are emitted synchronously after the DB write, while the Room-flow emission + combine recompute are async → `.value` was the PRE-write list: new albums never added AND `applyFilteredToAlbum(key, emptyList)` REMOVED existing albums touched by the scan. Rule: when reacting to a cache/settings event, read the fresh cache (hot cache is merged before the event fires) + current settings, not the derived `stateIn` flow's `.value`. Helper: `freshFilteredLibrary()`.
- A later LAZY refresh event (ON_RESUME after the folder picker closes) REPLACED a pending INCREMENTAL global in `handleChangeEvent` (unconditional `pendingGlobal = event`), and `loadAudioFiles` cancelled `scanJob` unconditionally — a LAZY no-op could kill a mid-flight whitelist incremental before `updateCache`, producing "scan logged, UI never updated" with no retry. Rule: merge strategies strongest-wins (FORCE > INCREMENTAL > LAZY) and let a LAZY no-op never cancel an in-flight scan.
- `refreshOnResume`/`SnapshotCheck` were downgraded to `RefreshStrategy.LAZY`, which skips the scan whenever cache exists — silently breaking the lesson #14 guarantee that resume/cold-start runs the incremental purge for SAF-only external deletions. Rule: resume/cold-start must stay INCREMENTAL; INCREMENTAL is a diff scan (MediaStore `DATE_MODIFIED > lastScan`, mtime compare), NOT a full rescan — release the skeleton as soon as `hasCache` is confirmed so it runs in the background without flashing the loading state.
- Double-scan in `DirectoryScanStrategy.scanDirectoriesIncremental`: a separate `newPaths`/`newFiles` pass re-read every file that was also in `pathsNeedingRescan` (`getFilesNeedingRescan` = `cached == null || mtime differs`, so new ⊆ needing-rescan). Rule: one rescan pass over `pathsNeedingRescan` covers both new and modified files; don't derive a second "not cached" set from `cachedInDirs`.
- Global path-only purges (`cleanupDeletedFiles(queryAllPaths())` in `IncrementalScanStrategy` and the periodic worker) would delete cached files in selected dirs that MediaStore doesn't index (USB/SD volumes, unindexed files). Rule: a global purge must exclude paths under user-selected directories (per-dir scans own deletion handling there).
- Purge decisions must distinguish "directory is genuinely empty" from "directory is inaccessible": a scoped-storage File-walk failure or missing SAF tree URI yields an empty enumeration, and treating it as empty purges every valid cached file inside. Rule: enumeration APIs return `accessible` + files; only purge against trees that were actually reachable.

## 25. UI state mirroring persisted data must be derived, not snapshotted
- Settings source-priority dialogs copied `enabled`/`extraOptions` from DataStore into a one-shot `MutableStateFlow` snapshot on open; `setSourceEnabled` wrote DataStore but never re-published the snapshot, so switches only reflected their new state after closing/re-opening the dialog. Rule: never copy persisted data into a mutable snapshot — derive it from the source flow (`combine(sourceFlow, interactionState)`); keep ONLY genuinely transient interaction state (e.g. in-drag source-ID order, draggedIndex) in the MutableStateFlow. Deriving makes staleness impossible by construction and removes the sync-collector/guard class of bugs entirely.

## 26. Persisted derived-state fingerprints need deterministic reads; MediaStore-version skips are SAF-gated
- Adding an aggregate snapshot to avoid the cold-start rebuild, the fingerprint that gates hydration was first built from `filterSettings.value` — a `stateIn` whose initial value on cold start is the ALL-DISABLED placeholder until DataStore emits (~100ms later). Hydrate would compare placeholder-fingerprint vs last-session real-fingerprint, never match, and the snapshot would be dead weight (plus a redundant rebuild when the real settings land). Rule: when a persisted derived state is validated by a fingerprint, build the fingerprint AND the state from deterministic reads (`first()` on the raw DataStore flows), never from a `stateIn` placeholder; also keep the stateIn's own collectors skip-guarded by comparing the same fingerprint so the placeholder→real transition doesn't re-run the rebuild it just hydrated from.
- Restoring the MediaStore version short-circuit (`MediaStore.getVersion` equality skips the incremental scan) is only sound when NO SAF whitelist dirs are configured: MediaStore bumps its version on any audio-row change, but external deletions inside SAF trees never touch it, so they need the per-dir filesystem walk on resume/start. Rule: a version-equality skip must be bypassed whenever `selectedDirectoryUris` is non-empty — the SAF path is the guaranteed purge point (lesson #14) and must never be version-gated.

## 27. Incremental mtime diffs must compare like-for-like mtime sources
- The SAF enumeration fallback (`queryDirectoryViaSaf`) returned `DocumentFile.lastModified()` values, while the Room cache stores `File.lastModified()` (written at scan time). SAF providers can round/truncate mtimes differently than the filesystem, so every cached mtime "differed" from the walk → `getFilesNeedingRescan` returned ALL files → full TagLib re-read on every launch (the "full rescan" the user sees as 2s of scanning per cold start, even when nothing changed). Rule: whenever an incremental diff compares mtimes against cached values, both sides must come from the same source — enumerate via SAF but re-stat the real path with `File(path).lastModified()` (fall back to the SAF value only when the file is genuinely unstatable), and keep a defensive tolerance (|a−b| ≤ 1s) in the diff so sub-second precision differences never force a re-read.

## 28. UI availability gates must follow data readiness, not the scan pipeline
- Cold start with a whitelist dir showed a 1s+ skeleton: `_isInitialLoad` (the skeleton gate) flipped false only inside `loadAudioFiles`, which is delayed by the event-bus merge window (400ms) + VM init delay + `hasCachedData()` probes — while the aggregator had ALREADY rendered the cached library (snapshot hydration / filteredAllAudios) at ~700ms. The user saw "can't display data directly": splash → skeleton → data, with the data waiting on a scan that wasn't even needed for display. Rule: any "has content" gate (skeleton, empty-state) must follow the DATA source (cache materialized), not the SCAN pipeline — flip `_isInitialLoad` from a `libraryInitialized && hasCachedData()` collector instead of inside the scan entry point; scans then reconcile in the background without ever hiding cached data. Also: the first ON_RESUME fires during onCreate and duplicates the cold-start SnapshotCheck request — skip it so the merge window doesn't delay the single real scan.

## 29. Screen-facing library flows: one owner, app-scope Eagerly, VMs are proxies
- Albums/Artists flashed an empty first frame on first tab entry while Files didn't: their ViewModels (created LAZILY on first navigation) re-wrapped the aggregator's already-hot StateFlows with `stateIn(WhileSubscribed(), initialValue = emptyList())` — first emission is always the empty initial, then the upstream (DataStore sort-option read / a Default-dispatcher mapping) fills it. Files didn't flash only because its VM is created eagerly in MainActivity and pre-warmed. Rule: never re-wrap an already-hot StateFlow in another `stateIn` with an `emptyList` initial inside a lazily-created ViewModel — instead expose the data as an app-scope `SharingStarted.Eagerly` projection owned by the data layer (AudioFileScanner), hot and correct before any navigation; ViewModels become pure pass-throughs (plus interaction state like sort persistence / scroll). This also kills the per-tab re-computation cost of `WhileSubscribed()` (upstream restarts on every tab return) and structurally removes the empty-first-frame bug class. Side benefit: the Eagerly collectors pre-warm UiStateDataStore at app start, so every DataStore-backed combine emits within a frame.

## 30. Cover flash: resolve-once + layered placeholders + reactive memory pre-warm
- Album/artist covers flashed on first tab entry because `AlbumArtImage` rendered EXCLUSIVE branches (shimmer XOR AsyncImage): the moment the URI resolved, the shimmer vanished into Coil's empty painter (AsyncImage had no placeholder), producing a blank gap before the crossfade — on ~15 cold cards simultaneously. Also, Coil's memory cache is process-lifetime, so every cold start re-decoded all visible covers. Rules: (1) never swap placeholder/image branches — layer the placeholder UNDER the AsyncImage and gate it on an `onSuccess`-tracked `imageLoaded` flag, so there is no blank gap by construction (memory-cache hits set it in the same frame); (2) pre-warm covers reactively — observe the unified display flows (sortedAlbums/artistListItems) and enqueue the first screen into Coil's memory cache with the renderer's EXACT `memoryCacheKey(uri)` and display-size pixels; verified via javap that Coil 3 `MemoryCache.Key` = (memoryCacheKey, extras) with NO size component, so any same-key pre-warm hits; (3) keep the pre-warm's cover-source selection identical to the renderer's (same `firstOrNull { albumId > 0 }` file), or the resolved URI differs and the key misses.

## 31. Floating overlay bars must not reserve Scaffold space; contentPadding ≠ zero with contentWindowInsets=0
- The floating pill nav bar showed a tall near-black band between the list and the pill: the content slot was wrapped in `Modifier.padding(innerPadding)` where `innerPadding.bottom` = the bottomBar slot's measured height (status inset + 56dp pill + 16dp lift + gesture-nav inset ≈ 140-170dp). M3 Scaffold measures content with the FULL window (looseConstraints = `constraints.copy(minWidth=0, minHeight=0)`) and draws the bottomBar ON TOP (`BottomBarZIndex=3 > ContentZIndex=0`), so padding content by the bar height leaves an empty strip showing the Scaffold's `containerColor` (near-black in dark theme) instead of content scrolling under the pill. Also, `contentPadding` includes topBar/bottomBar heights even when `contentWindowInsets = WindowInsets(0)` — it's zero only when those slots are empty. Rule: reserve `innerPadding` only when the bottom slot is OPAQUE (standard NavigationBar); a floating overlay bar must NOT reserve space — keep content edge-to-edge and let the bar draw over it.

## 32. Edge-to-edge: scrollable lists must reserve the dynamic system nav inset, not a fixed dp
- OnlineCoverSearchScreen's results list used a fixed `contentPadding = PaddingValues(bottom = 16.dp)` while its parent Column only applied the Scaffold's TOP inset — on 3-button-nav devices (48dp inset) the last cover-result card was drawn under the system navigation bar. Rule: in an edge-to-edge Scaffold, the bottom of any scrollable content must be `decorativeGap + <dynamic inset>` — either `innerPadding.calculateBottomPadding()` (Scaffold slot) or `WindowInsets.navigationBars.asPaddingValues().calculateBottomPadding()` (bare composables) or a ModalBottomSheet's automatic inset. Fixed dp values are acceptable ONLY as the decorative gap above the inset (8/12/16dp) or as space reserved for a fixed-height floating toolbar (80dp); they must never substitute for the system inset itself, which varies by device (gesture 24dp vs 3-button 48dp).

## 33. Wrapping M3 components: mirror the slot API, and mind duplicate imports after refactors
- The thin `VoxlyScaffold` wrapper omitted `floatingActionButton`; `MetadataEditorScreen` passed an empty `floatingActionButton = {}` and broke with "No parameter with name 'floatingActionButton'". In the same refactor, an edit left TWO `import androidx.compose.material3.TopAppBarDefaults` lines in AlbumDetailScreen → "Conflicting import: imported name 'TopAppBarDefaults' is ambiguous". Rule: when wrapping an M3 component for reuse, either mirror its full slot set (topBar/bottomBar/snackbarHost/FAB) or drop the parameter from call sites; after bulk edits, grep for duplicate imports of a symbol the compiler flags as ambiguous — the edit tool cannot detect duplicates, only the compiler can.

## 34. Directory incremental enumeration: MediaStore-first, not a recursive File stat walk
- Cold-start splash was held by a ~1.9s `collectDirectoryFileModificationTimes` File walk for a 676-file whitelist dir (per-file `listFiles`/`isDirectory`/`canRead`/`lastModified` stats on the UI-critical path) when MediaStore already indexes the tree (`RELATIVE_PATH` range query + per-path `File.lastModified()` re-stat is ~50ms). Rule: for primary-storage whitelist dirs, enumerate via MediaStore's `RELATIVE_PATH = ? OR LIKE ?` range query (indexed), then re-stat each real path with `File(path).lastModified()` — mtimes must stay like-for-like with the cache (lesson #27); MediaStore `DATE_MODIFIED` is second-precision AND lags external edits until its scanner observes them, so diffing against it would silently miss edits.
- Safety nets that must stay: (1) fall back to the File walk when the dir is not on primary storage (root dir, USB/SD volumes — MediaStore can't scope the query), when the query returns empty (ambiguous: empty vs unindexed, lesson #24), or when a completeness check finds a cached path missing from MediaStore that still exists on disk (`File(path).exists()` only for the missing set — zero cost when complete); (2) skip MediaStore rows whose real path no longer stats (`mtime <= 0`), so deletions are purged immediately instead of MediaStore's stale row keeping a phantom entry (lesson #14); (3) load the full cached (path, mtime) batch ONCE per scan and reuse it for both the completeness check and `getFilesNeedingRescan` instead of two separate queries.

## 35. Preview-flow operators (`debounce`, `sample`, …) need `FlowPreview`, not just `ExperimentalCoroutinesApi`
- `AlbumArtistAggregator` (3× `debounce`) and `CoverPreloadManager` (1× `debounce`) compiled with warnings: "declaration is in a preview state … mark with '@kotlinx.coroutines.FlowPreview'". `@OptIn(ExperimentalCoroutinesApi::class)` was present on both classes — the opt-in families are separate marker annotations, so it does NOT cover `FlowPreview`-gated operators. Rule: when a class uses preview flow operators, opt into BOTH families explicitly: `@OptIn(ExperimentalCoroutinesApi::class, FlowPreview::class)` (already the codebase pattern in ReplayGainScanner/MediaStoreChangeWatcher/OnlineMetadataViewModel); grep new/edited files for `debounce|sample|flatMapMerge|conflate` and check the class-level `@OptIn` before compiling.

## 36. FTS4 `MATCH` silently returns nothing for non-ASCII content — and the fix is NOT another search path
- Search returned zero results everywhere (Albums/Artists/Home used a Room `FTS4 MATCH :query || '*'` query; the Files tab used an in-memory `contains` filter; directory contents searched only the current directory). Root cause 1: FTS4's default `simple` tokenizer only emits runs of ASCII alphanumerics — CJK/accented metadata (the norm in Chinese libraries) produces ZERO tokens, so every Chinese query matched nothing; the FTS table also indexed only title/artist/album, never the filename. FTS4 `MATCH` fails silently (empty result, no error) on untokenized content. Root cause 2: THREE divergent search implementations (in-memory, FTS, directory-scoped), each with its own failure mode — two paths meant two bugs.
- Rule: FTS4 needs an explicit language-aware tokenizer AND every searchable field declared as a column, else it silently no-ops; if substring (infix) search across arbitrary scripts is required, FTS4 is the wrong tool. But the bigger rule: **one search path, derived from the data the UI already renders**. The unified fix filters `filteredAllAudios` (the same filtered-library StateFlow the screens display) with a case-insensitive substring check over name/title/artist/album on `Dispatchers.Default`, debounced 250ms in the sheet. This is correct for every language/position, respects whitelist/blacklist/min-duration settings by construction (a SQL query cannot see those settings without duplicating the FilterEngine logic), never touches the main thread, and is reactive to library changes — one implementation, zero divergence. The dead FTS4 table + Room sync triggers were fully dropped (v17→v18 migration must `DROP TRIGGER` the 4 `room_fts_content_sync_*` triggers BEFORE `DROP TABLE`, or the next base-table write throws "no such table").

## 37. `callbackFlow` producer + its `supervisorScope { launch { } }` children run on the COLLECTOR's dispatcher — blocking I/O there freezes the UI
- Online metadata search showed a stuck loader then an ANR ("应用卡死"). Root cause: `OnlineMetadataViewModel.searchInternal` collects the aggregated search flow from `viewModelScope.launch` (Main). `callbackFlow` producers execute in the collector's context, and `supervisorScope { launch { ... } }` children inherit it — so `AggregatedOnlineMetadataRepository.searchByTrackFlow` → each source's `searchByTrackFlow` → `TengxRepositoryImpl.searchSongs/getLyrics` all ran on the **Main thread**. `TengxRepositoryImpl` (QQ Music, commit 1982cd82) was the only network repo whose methods lacked `withContext(Dispatchers.IO)` — iTunes/MusicBrainz/NetEase wrap theirs. Its raw `Response<ResponseBody>` + `response.body()?.string()` blocking reads, `JsonParser` parsing, DESede decrypt and Inflater decompression (`QQMusicLyricCrypto`) froze the main thread; the loader never resolved and the app ANR'd.
- Rule: in any flow-driven online search/lyrics pipeline, the data-layer repository methods that perform blocking I/O or heavy CPU (body `.string()`, JSON parse, crypto, decompression) MUST be wrapped in `withContext(Dispatchers.IO)` themselves — do not rely on the flow being collected off-main, because `callbackFlow` + `launch` inherit the collector's dispatcher (Main in ViewModels). Audit every source repo the same way (`rg -l "callbackFlow" data/` then check each for `withContext`); a raw `Response<ResponseBody>` that is `.string()`-read is the classic main-thread blocker. Also: converting a method to `withContext(Dispatchers.IO) { ... }` makes the lambda `crossinline` — inner non-local `return` statements stop compiling; restructure to expression-style `Result` values.

## 38. Edit-tool deletion: an anchor at the END of oldText that includes the NEXT function's header will delete it too
- Removing the obsolete `SourceItemCard` in SettingsScreen.kt, the deletion `oldText` ended with `...}\n\n@OptIn(...)\n@Composable\nfun PerSourceSearchLimitRow(` and `newText` was empty — the tool matched the whole block and the `PerSourceSearchLimitRow` header (OptIn/Composable/fun + its parameter list start) was silently swallowed with it, leaving an orphaned function body (`title: String, ...` at top level) and cascading "@Composable invocations can only happen..." errors at the next function's site. The fix was a manual re-insertion of the header lines.
- Rule: when deleting a block, the trailing anchor lines of `oldText` MUST be re-emitted verbatim in `newText` unless you intend to delete them too — an anchor is matched and REPLACED, not "checked". Keep anchors minimal (a unique closing `}` or a short unique fragment); if the next symbol (function signature, KDoc, annotation) must survive, put it only in `newText`. Same class as lesson #20 (deleting a function body orphaned its KDoc): deletion edits are exact-text replacement, so anything in `oldText` not reproduced in `newText` is gone.

## 39. Scope extensions shadow top-level functions with the same name — use fully-qualified calls
- `SourceSettingsScreen` renders its card list inside `Column { Box { AnimatedVisibility(...) } }`. The call failed with "`fun ColumnScope.AnimatedVisibility(...)` cannot be called in this context with an implicit receiver" — inside a `ColumnScope` receiver, the scope's `AnimatedVisibility` extension (the expand/collapse variant) shadows the top-level `androidx.compose.animation.AnimatedVisibility`, and the compiler refuses the implicit-receiver dispatch. Also: `PaddingValues.calculateBottomPadding()` is a MEMBER function, not an extension — `import androidx.compose.foundation.layout.calculateBottomPadding` is a compile error (unresolved); the member resolves with no import.
- Rule: when calling a top-level function that has a same-named scope extension (AnimatedVisibility, Scaffold's content, etc.) from inside that scope's receiver, qualify it fully (`androidx.compose.animation.AnimatedVisibility(...)`) or move it out of the scope; and before adding an `import` for something that "looks like" an extension, check whether it is a member of the receiver type (PaddingValues.calculateBottomPadding, IntOffset.x, etc.) — importing a member as an extension is an unresolved-reference error.

## 38. 搜索结果排序：用字典序分层替代加权分数，避免异质维度调参
- 原排序 `relevanceScore × 100 + (maxPriority-1-index) × 2` 把相关性（3-9 分制）和源优先级（4 源最多差 6 分）揉进一个数字：优先级权重被相关性放大系数完全碾压，设置页拖拽的源顺序对结果几乎无感；同时 `sortedByDescending(selector)` 的比较器在每次比较时重算 selector（O(n log n) 次 Levenshtein），且 `searchByArtistAlbum` 时 title 为空导致标题维度全部同分、排序退化为纯优先级。
- Rule: 两个异质维度的排序不要线性加权调参——用**字典序分层**：`compareBy { tier }.thenBy { sourceRank }.thenByDescending { relevance }`。相关性档位（EXACT > PREFIX > CONTAINS > FUZZY > NONE）绝对主导，源优先级只在同档内生效，等价于组合分 `tier × 源数量 + sourceRank`，零魔法数字且可解释。decorate-sort-undecorate（先 map 算键再排序）同时消除比较器内 selector 重算。多个调用方（flow/非 flow 路径）必须复用同一个 Sorter，避免 `AggregatedOnlineMetadataRepository.finalizeReleaseResults`（只按优先级排）与 `OnlineSearchSorter`（相关性主导）两套逻辑分裂。
- 语义分界点需产品确认：低优先级源的 exact match 会排在所有高优先级源的 partial match 之前（tier 绝对主导）；若要求"高优先级源的前缀匹配压过低优先级源的完全匹配"则必须回到加权调参（不推荐）。

## 40. `Modifier.pointerInput(Unit)` captures FIRST-composition callbacks — wrap them in `rememberUpdatedState`
- Source order cards (LazyColumn `items(key = sourceId)`) reuse their composable when the list reorders, and the card's `pointerInput(Unit) { detectDragGesturesAfterLongPress(onDragStart = { onDragStart() }, ...) }` block only runs once — it captured the `onDragStart` lambda from first composition, which had the ORIGINAL displayIndex baked in (`startDragging(0)`). After dragging A from slot 1 to slot 3, the pointer input on A's card still called `startDragging(0)`, so long-pressing A dragged the source that now sat at slot 0 (the "wrong card" bug). `remember { }`-free recomposition updates the lambda parameter but NOT the already-running pointerInput block.
- Rule: any callback read inside a `pointerInput(key)` block must be the latest value — wrap the callback in `val current by rememberUpdatedState(callback)` and invoke `current()` inside the block (or make the callback index-free, e.g. pass a stable id and resolve the index in the ViewModel). This applies to every long-lived gesture handler whose behavior depends on list order / item position.

## 39. 结果列表字段合并：`?:` 不覆盖空字符串 — 空专辑名/空歌名会堵住真实值
- 元数据搜索页网易云/QQ 源结果"歌手旁不显示专辑"。根因 1：`mergeRelease` 里 `albumTitle = old.albumTitle ?: incoming.albumTitle` —— 网易云 track 搜索在 detail 请求失败时产出 `albumName = ""`（空串而非 null），同 id 另一源的 `albumTitle = "真实专辑"` 用 `?:` 无法覆盖空串，专辑名被永久丢弃（`"" ?: "真名"` = `""`）。根因 2：UI 侧 `albumTitle` 缺失时 fallback 到 `release.title`（歌名），而 `songTitle` 也是 `release.title` → `albumTitle == songTitle` → 显示条件误判为"专辑名==歌名"而隐藏。
- Rule: 合并 nullable 字段时，凡是数据源可能产出空字符串的字段（`albumTitle`/`songTitle` 等），必须用 `old.takeIf { it.isNotBlank() } ?: incoming` 而非裸 `?:`（后者只处理 null 不处理空串）；与同函数里 `title`/`artist` 的 `isBlank()` 判断保持一致。UI 侧"有专辑才显示"的判断不要 fallback 到歌名去比较——直接 `albumTitle?.takeIf { it.isNotBlank() }` 取真值，缺失就不显示。

## 40. 增量编译 UP-TO-DATE 不验证工作副本——未提交改动中的编译错误要等全量重编译才暴露
- 会话开始时 `compileGithubDebugKotlin` 显示 "8 tasks UP-TO-DATE / BUILD SUCCESSFUL"，实际工作副本里 `ScanDirectorySettingsScreen.kt`（他人/上一会话未提交的重构）从 `androidx.compose.runtime` 导入了 `MutableInteractionSource`（真实包 `androidx.compose.foundation.interaction`）。改动没触及该文件的依赖时 Gradle 跳过重编译，错误被掩盖；一旦改了 strings.xml 等资源触发 `packageGithubDebugResources` → 全量 Kotlin 重编译，才突然报 3 个 `e:`。Rule: 会话开头的 UP-TO-DATE 编译 ≠ 代码健康；在未提交改动较多的工作副本里做任何修改后，若想确认整个仓库可编译，需要触发一次真正的全量编译（改资源文件、`--rerun-tasks` 或 `clean`），并 grep `^e:` 检查非本文件的错误——增量跳过会隐藏他人遗留的断点，让后续任务在错误的"编译通过"假设上展开。

## 41. 整块删除时 oldText 必须覆盖块的首部（`if`/`fun` 头）到尾部的全部范围
- 删除第二个确认对话框（`if (pendingDeleteSeparator != null) { AlertDialog(...) }`）时，oldText 只匹配了块的**尾部**（`dismissButton = {...}\n        )\n    }\n}`），newText 为一个 `}`——结果尾部四行被压成一个 `}`：`if` 头、未闭合的 `AlertDialog(` 调用和 confirmButton 悬空在函数体内，函数右花括号被吞，下一个 `@Composable` 头被吞进函数体。Read 检查立刻暴露（`if (pendingDeleteSeparator != null) {` 后面直接跟 `}`），需再补一次 edit 删除悬空块。Lesson #38 讲的是"尾锚被吞"；这次是"头被留下"——同一个工具陷阱的反面。
- Rule: 删除一个完整块时，oldText 必须从块的第一行（`if (...) {` / `fun ...` 头）覆盖到最后一个右花括号，newText 只保留必须存活的边界（如外层函数的收尾 `}`）；只匹配尾部会让头部悬空。删除后用 Read 复核块边界，或直接编译。

## 42. ColumnScope.AnimatedVisibility 阴影不只在直接接收者上——外层隐式接收者也触发
- 分隔符对话框里在 `FlexBox` 内容 lambda 中调用 `AnimatedVisibility`，编译报 "'fun ColumnScope.AnimatedVisibility(...)' cannot be called in this context with an implicit receiver"。FlexBox 自身的 `FlexScope` 没有 AnimatedVisibility 扩展，但 `FlexBox` 是 `ColumnScope.FlexBox(...)`（其 content 是 `FlexScope.() -> Unit`），外层 ColumnScope 仍是隐式接收者——阴影来自任何一层的隐式接收者，不限于直接接收者。Lesson #39 的规则正确但没覆盖"外层接收者"这一情况。
- Rule: 只要某 composable 位于 Column/Row（或 ColumnScope/RowScope 扩展如 FlexBox、FlowRow）内部任意层级，调用顶层 `AnimatedVisibility` 时一律完全限定 `androidx.compose.animation.AnimatedVisibility(...)`，不要依赖"直接接收者无同名扩展"的推断。
